Model choices

Two deployment models. One Spring AI integration.

Laya and Jev both answer typed choice, score and noul questions through the System One API. They solve different operational needs, so the right approach is to use each deliberately.

Laya

Private, self-hosted decisions

Open-weight Laya runs where your application runs. It gives teams a local path for frequent, bounded decision tasks and an option to fine-tune on their own labelled examples.

  • Apache 2.0 and self-hosted
  • Data remains on your infrastructure
  • Fine-tuning workflow for domain-labelled data
  • Local development and CI without a hosted API key
  • Server-side routing, abstention and batch inference
Jev

Managed decisions for managed operations

Jev is the hosted TypeSafe decision model. It is the natural choice where teams want a managed service, broad zero-shot coverage, or a larger decision space without operating inference infrastructure.

  • Hosted API with no model-serving work
  • Strong fit for broad and many-option choices
  • Published multilingual benchmark coverage
  • Use it as the escalation path for selected work
  • Same typed questions and Spring AI components

Use cases

Where local typed decisions create leverage.

The best first deployments are high-volume, bounded decisions where local data handling and repeatable routing matter.

01

Private RAG triage

Screen retrieved passages for relevance and obvious injection attempts before they reach the LLM. Keep Laya beside sensitive documents. Escalate only the cases your policy marks uncertain.

02

Support routing

Route short, English tickets through a stable set of queues such as billing, technical support and account access. Fine-tune on your own historical labels when the language is domain-specific.

03

Agent tool selection

Choose among a bounded set of tools before an agent runs them. Preserve an authorization layer for side effects, then escalate low-confidence or high-impact choices.

Developer tutorial

Start local. Keep the application code stable.

The Laya adapter is a TypeSafeClient. Existing Spring AI components retain their APIs, while the adapter handles Laya-specific confidence, batching and observability.

1. Run Laya

Run the self-hosted server. The first startup downloads the configured checkpoint.

# CPU example
uv venv --python 3.12
uv pip install --torch-backend=cpu \
  "laya[serve]"

LAYA_MODELS=english \
LAYA_DEFAULT_MODEL=english \
LAYA_PRELOAD=1 \
laya-serve

2. Select Laya in Spring Boot

Adding a base URL creates a Laya-backed TypeSafeClient. Existing builders keep working.

application-laya.properties
spring.ai.laya.base-url=http://localhost:8000
spring.ai.laya.model=auto
spring.ai.laya.confidence-metric=jev
spring.ai.laya.options.min-confidence=0.75

# For high-volume CPU work, tune after measuring:
spring.ai.laya.rows-per-batch-call=16
spring.ai.laya.max-concurrent-batch-calls=1

3. Reuse existing Spring AI components

The filter receives a Laya-backed TypeSafe client. Compatible work automatically uses the Laya batch endpoint.

RAG configuration
@Bean
JevDocumentFilter documentFilter(
    TypeSafeClient client) {
  return JevDocumentFilter.builder(client)
      .build();
}

4. Enable the managed path when you need it

A hybrid client keeps local handling for qualifying requests and routes selected cases to Jev. Escalated requests, including their full state, are sent to the Jev service, so the starter refuses to start until spring.ai.laya.escalation.allow-external-data-export=true confirms the export is approved.

application-hybrid.properties
spring.ai.typesafe.api-key=${TYPESAFE_API_KEY}
spring.ai.laya.escalation.enabled=true
spring.ai.laya.escalation.allow-external-data-export=true
spring.ai.laya.escalation.min-answer-confidence=0.75
spring.ai.laya.escalation.max-laya-choice-options=20
Important: validate thresholds per checkpoint and workload.

Laya's native confidence is entropy-based. The adapter defaults to the Jev formula so existing Jev thresholds retain their intended meaning. For Laya-specific gating, tune against answer_confidence using labelled examples from your own workload.

Benchmarking

Reproduce the comparison before you adopt it.

The benchmark stays local to the repository. It has no dependency on the GitHub Pages site and records the inputs needed to review a result.

Run a strict side-by-side comparison.

Start local Laya, set an authorized TYPESAFE_API_KEY, then run the benchmark with -Dbench.requireBoth=true. It writes a parity receipt and refuses to report if either backend returns fewer decisions than the fixed input count.

PowerShell
$env:LAYA_BASE_URL = 'http://localhost:8000'
$env:TYPESAFE_API_KEY = 'your-Jev-key'
mvn -pl laya-benchmarks exec:java `
  '-Dbench.requireBoth=true' `
  '-Dbench.laya.model=english' `
  '-Dbench.jev.model=jev-latest'
